## 一句話

工具每個禮拜都在換，你追不完 — 但底下那層概念幾乎沒動過，那才是你該追的東西。

## 三分鐘講稿

先講一個大家都有的焦慮。Claude Code、Cursor、Codex、Harness、各種新 LLM⋯⋯每個禮拜都有新東西冒出來，到底要跟哪一個？好不容易在公司建好一套 AI 開發流程，下禮拜大廠或 Open Source 就把你做的事整理得更漂亮。於是你天天在問：我到底該投入去建流程，還是繼續寫我的業務邏輯？還是乾脆像我一樣一直在玩新玩具（然後手邊的正事就🫠）？

我後來想通一件事。把現在的 AI 開發，用作業系統的角度看一遍：LLM 是 CPU、Context Window 是 RAM、Agent 是 Process、Prompt Context 就是現在的「Code」。

一旦這樣對照，你會發現：工具在換，這幾個角色沒有換。名字天天新，但底層的概念層幾乎沒動。你焦慮的是「工具」這一層，但真正決定你能不能做出東西的，是下面那層概念。

這整站要教的，就是這層不會過期的東西。搞懂「AI 是文字接龍」「Context 是它的全部世界」「Agent 是怎麼被組出來的」，你手上換成哪個工具，都能馬上上手 — 因為你認得它在作業系統裡是哪個角色。

所以請不要再為了追最新的架構把自己搞得很累。一直刻意追最 fancy 的新概念，不見得是好方向；只要能解決問題，從最簡單的一段 Prompt，到整套 Autonomous Agent，都是解法。找到最適合你專案跟團隊的方式，比追工具重要一百倍。

這就是為什麼這門課第一章不是教工具，是教概念。工具會折舊，概念不會。

## 關鍵重點

- 焦慮的來源是「工具層」每週更新 — 但工具底下的「概念層」幾乎不動
- 用 OS 類比鎖住不變的角色：LLM=CPU、Context Window=RAM、Agent=Process、Prompt=Code
- Code 一直都是工程師在 maintain — 換成 Agent 協作也一樣，回到人身上
- 解法沒有高下：一段 Prompt 到全自主 Agent 都算數，能解決問題就好
- 追概念的人換工具零成本，追工具的人永遠在重新學

## 互動示範構想

左邊一條「工具時間軸」快速滾動，每隔幾秒蹦出一個新工具名（Cursor → Codex → 某某 Harness → 某某 plugin⋯），營造「追不完」的壓迫感。右邊是一塊靜止不動的「OS 概念層」四格卡片（CPU／RAM／Process／Code）。使用者把左邊任一個新工具拖到右邊，系統就把它歸位到對應的概念格 — 體驗「不管冒出什麼新工具，都能對回同一層概念」。底部即時顯示：「你追了 N 個工具，它們全部對應到這 4 個概念。」

## 課堂提問

- 你上一次因為「又出了新工具」而焦慮，是什麼時候？那個工具改變的是概念層，還是只是工具層？
- 如果 LLM 是 CPU、Prompt 是 Code，那「誰負責 maintain 這段 Code」這個問題的答案，對你的工作有什麼提示？
- 面對一個沒看過的新 AI 工具，你要問的第一個問題應該是「它怎麼用」，還是「它在 OS 類比裡是哪個角色」？
