## 一句話

同一件事有三種接法 — 不是越底層越厲害，是你需要多大的鑰匙、扛不扛得起。

## 三分鐘講稿

先講一個診所真的遇到的需求。他們想讓 AI 每週自動把 Gmail 裡的發票附件抓下來、打包成一包。聽起來很單純吧？結果一路查下去，才發現這件小事會逼你穿過三層完全不同的接法。

第一層是 **connector（連接器）**。這是服務商幫你封裝好的東西 — 你到設定裡點一下、跳出授權頁、按同意，就能用了。Gmail connector 能讀信、能加 label、能寫信、能回信，日常需求其實很夠用。但我們去翻它的能力清單，就是**沒有下載附件**這一項。

一開始會覺得「幹嘛鎖成這樣」，但你想一下就知道很合理 —— connector 要是全開，一般 user 弄出事誰負責？Claude 要負責嗎？Gmail 要負責嗎？沒有人要幫你負責，那就是你的風險要自管。所以服務商乾脆先幫你鎖起來。**connector 的本質，是別人幫你把風險封裝掉，代價是能力被鎖死。**

connector 做不到，就往下掉一層 — **MCP**。這裡要講清楚一件很多人搞混的事：**MCP 就是 connector 底下實作的協定**；反過來說，**connector 就是有服務商幫你封裝好的 MCP**。它們不是兩個對立的東西，是同一條路的不同深度。官方 connector 做得不好、或缺你要的能力，你可以自己接第三方的 MCP server，甚至自己架一個 — 在本機 launch，拿到一個 127.0.0.1 開頭的網址，資料連外網都不用走。

代價是什麼？難度中等，而且**授權要你自己過**。我們課堂上就當場踩到 — 接 Notion 的時候授權卡在 callback 壞掉，怎麼點都回不來。這件事本身就是一課：**工具會壞，不要太相信別人寫的 code。** 你往下掉一層，就多接手一層別人不再幫你扛的東西。

再往下，最底層，是 **API key**。拿到 API key，你就等於天神了 —— 那把鑰匙能開你 Gmail 的一切。但你要自己去 Google Cloud Console 開專案、啟用 API、建 OAuth 憑證，流程繁瑣到會勸退很多人。有人會問：那我把權限縮小一點，只給讀不給寫呢？可以啊，但你都用到 API key 了只能讀不能寫，好像也說不過去。

所以整條光譜長這樣：**Connector → MCP → API key**。它們其實都是 API，只是 package 過的 API — 差別只在誰幫你封裝、你拿到多大的權限、你扛多少風險。

判斷法則很簡單，而且方向是**由上往下**，不是由下往上：**能用 connector 解決，就不要往下掉**。connector 真的做不到（像我們那個下載附件打包），才掉到 MCP；MCP 還是搞不定，才動 API key。每往下一層，能力變大、設定變繁瑣、風險從服務商身上移到你身上。

最後補一句：技術上你當然可以直接從 API key 開始 — **你夠強可以啊，不是每個人都可以。** 對大多數人、大多數任務，這時候就很適合退回 connector，因為 connector 都幫你封起來了。

## 關鍵重點

- 三層是同一條光譜，不是三種技術：connector 是服務商封裝好的 MCP，MCP 底下還是 API — 它們都是 package 過的 API
- Connector：點開授權就能用，代價是能力被鎖死（Gmail connector 能讀信、加 label、寫信、回信，就是不能下載附件）— 鎖起來很合理，因為出事沒人幫你負責
- MCP：官方 connector 不夠用時，接第三方或本機自架（127.0.0.1，不用走外網）；難度中等、授權要自己過，而且工具會壞 — 別太相信別人寫的 code
- API key：最底層、「等於天神」，但要 Cloud 專案＋啟用 API＋OAuth 憑證，流程繁瑣、風險 100% 自負
- 判斷法則由上往下：能用 connector 解決就別往下掉；connector 做不到才用 MCP，MCP 還不行才動 API key
- 每往下一層＝能力變大、設定變繁瑣、風險從服務商移到你身上 — 選的不是「厲害」，是「你扛不扛得起」

## 互動示範構想

一個「任務 × 三層軌道」的對照台。上方是四個任務按鈕：讀最新 10 封信／幫信件加標籤／下載附件打包到資料夾／每週自動排程跑。下方是三條並排的層級軌道：Connector、MCP、API Key，每條軌道右邊掛著三根代價量表（設定成本、權限範圍、風險自負）。

點任何一個任務，三條軌道即時亮燈：綠燈＝做得到、黃燈＝做得到但有附帶條件、紅燈＝這一層根本沒有這個能力，並在燈旁寫出理由（例如 connector 那格會攤開它的工具清單，讓你親眼看到「下載附件」不在裡面）。

導演節奏：先用「讀信、加標籤」證明 connector 全包（三根量表都很低，風險條寫「服務商扛」）→ 切到「下載附件打包」，connector 那格變紅、清單抖動、標出缺口 → 往下掉一層，MCP 軌道亮起，同時三根量表跟著長高、風險條從「服務商扛」翻成「一半自負」→ 再掉到 API Key，全綠但量表全滿、風險條寫「100% 自負」→ 最後開放 sandbox，讓使用者自由切任務、自己讀出「能用 connector 就別往下掉」這條心法。

## 課堂提問

- 你現在最想叫 AI 做的那件事，connector 夠不夠？你有真的去翻過它的能力清單嗎？
- 「connector 全開，一般 user 弄出事誰負責？」— 這個問題怎麼影響你選哪一層？
- 你手上有哪個任務，是真的值得你跑一趟 Google Cloud Console 去申請 API key 的？哪些其實不值得？
