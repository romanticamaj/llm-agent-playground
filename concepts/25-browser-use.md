## 一句話

你叫 AI「上網查一下」，它多半沒開瀏覽器 — 它讀的是搜尋引擎**事先收錄好**的那份副本。

## 三分鐘講稿

先問一個問題：你跟 AI 說「幫我上網查一下這個」，你腦中浮現的畫面是什麼？大概是它打開一個瀏覽器，把網頁捲一捲、讀一讀，然後回來跟你講。

**其實大部分時候，它根本沒開瀏覽器。**

它走的是一條叫 **Web Search** 的路 — 直接打搜尋 API，把結果拿回來讀。沒有視窗、沒有捲動、不用等網頁載入。又快又便宜，所以現在所有付費的 LLM 訂閱都內建了這條：Claude、ChatGPT、Gemini、Perplexity，全部都有。你平常叫 AI 查資料，九成走的是這條。

那既然這麼好用，為什麼還有人要大費周章讓 AI 去「操作瀏覽器」？

關鍵在這一句，這是全篇最重要的一句：**Web Search 拿到的，是搜尋引擎「事先收錄好」的版本。**

它不是即時去看那個網頁，是去搜尋引擎的倉庫裡，調一份早就抄好的副本。副本什麼時候抄的、抄到多少，你管不了。

想通這件事，四個限制自己就掉出來了。

第一，**內容要靠瀏覽器跑起來才會出現的**。現在很多網站，抓回來是一個空殼，真正的內容是瀏覽器執行完程式才塞進畫面的。搜尋引擎收錄的時候拿到的就是那個空殼 — 它看到一片空白，AI 也就一片空白。（相對的，內容在伺服器端就組好、直接吐出來的那種網站，大致拿得到。這兩種寫法各有名字，但名詞不重要，你只要記得：**有些網站的內容，是到你眼前才長出來的**。）

第二，**要登入才看得到的**。你的 Gmail、公司的 Notion、你的訂單記錄 — 搜尋引擎沒有你的帳號，它完全看不到。這不是抓不全，是零。

第三，**要點按鈕才出現的**。要展開、要切分頁、要按「載入更多」的那些內容，副本上就是沒有。

第四，**太新的**。剛發布的東西還沒被收錄，去倉庫裡調也調不到。

**只有撞到這四種情況，才需要真的把瀏覽器開起來。**

而開起來又有兩條路。分水嶺很好記：**是共用你已經登入的那個瀏覽器，還是另外開一個乾淨的？**

第一條是 **Claude in Chrome** — 共用你的瀏覽器。它接管你平常在用的那個 Chrome，你已經登入的 Gmail、Notion，它一開就讀得到，不用再授權一次。碰到登入頁或 CAPTCHA，它會**停下來、把控制權交還給你**，等你手動處理完再繼續 — 這是它最貼心的設計。它有三個入口：Claude 網頁裡的 connector、Claude Desktop、Claude Code 的 `--chrome`；但你不用記，因為背後是同一套東西。缺點是它偏封閉，主要服務 Claude 自家生態。

第二條是 **Playwright** — 另外開一個乾淨的。它在你電腦上起一個全新的瀏覽器，跟你日常那個**完全隔離**：沒有你的登入狀態、沒有你的 cookie、沒有你裝的擴充套件。聽起來像缺點，但這正是它的賣點 — 因為乾淨，所以每次跑出來的結果都一樣；因為可重複，所以能丟到自動化流程裡天天跑。這就是為什麼寫 E2E 測試沒有第二個選擇。代價是它吃 token 很兇，每操作一步就把整頁的結構回傳給 AI 看一次。

講一個真實例子，這個例子一次打中兩個限制。我要幫我媽從蝦皮把訂單清單抄下來。蝦皮**沒有開放 API**，訂單又**要登入才看得到**。Web Search 在這裡完全廢掉 — 那份副本裡根本沒有我的訂單頁。最後怎麼解？用 Claude Code 的 `--chrome`，讓 AI 在我已經登入的瀏覽器裡，一頁一頁慢慢操作抄下來。

所以判斷法則就很清楚了，按你要做的事：

一般查資料 — **Web Search 為主**，撞到剛剛那四種情況，才退回去開瀏覽器。
要讀「你已經登入」的東西 — Claude in Chrome。
要抓沒開放 API 的服務 — Claude in Chrome 或 Playwright。
要寫 E2E 測試 — Playwright，沒得選，因為只有它同時給你乾淨、可重複、能上自動化流程。

最後補一句底層的洞察。這幾條路看起來差很多，其實底下都在做同一件事 — **讓 AI 跟瀏覽器的控制介面講話**。瀏覽器本來就開了一個給程式操控的入口（你按 F12 開開發者工具，用的就是同一套），這幾條路只是中間那層包裝不一樣：有的繞雲端、有的走本機。

所以不要問「哪一個最強」。要問的是：**我這件事，卡在哪一關？** 卡在內容拿不到？卡在要登入？卡在要可重複？你把卡點講清楚，答案自己就浮出來了。

這跟概念 20 是同一種思路 — 那邊說「能用 connector 就別往下掉」，這邊說「Web Search 夠用就別開瀏覽器」。同一句話：**選最淺可行的那一層，往下掉是有代價的。**

## 關鍵重點

- **翻轉**：叫 AI「上網查」，它多半沒開瀏覽器 — 走的是 Web Search，直接打搜尋 API，又快又便宜；所有付費 LLM 訂閱（Claude／ChatGPT／Gemini／Perplexity）都內建這條
- **全篇最重要的一句**：Web Search 拿到的是搜尋引擎**事先收錄好**的版本 — 不是現在那個網頁，是倉庫裡一份抄好的副本
- 副本拿不到的剛好四種：**要跑起來才長出來的動態內容**（收錄到的是空殼）、**要登入才看得到的**（完全是零）、**要點按鈕才出現的**、**太新還沒被收錄的**（伺服器端就組好的內容則大致拿得到）
- 撞到這四種，才需要真的開瀏覽器；而開起來的分水嶺是：**共用你已登入的瀏覽器，還是另開一個乾淨的**
- **Claude in Chrome（共用你的）**：直接沿用已登入狀態，Gmail、Notion 一開就讀；碰到登入頁或 CAPTCHA 會停下來把控制權交還給你。三個入口（網頁 connector／Desktop／Claude Code `--chrome`）背後是同一套。缺點偏封閉
- **Playwright（開乾淨的）**：本機起一個跟你日常瀏覽器完全隔離的瀏覽器 — 沒有你的登入狀態，但因為乾淨、可重複、能上自動化流程，所以是 E2E 測試的標配；代價是吃 token 兇（每步回傳整頁結構）
- **真實案例**：幫媽媽從蝦皮抄訂單 — 沒開放 API ＋ 要登入 → Web Search 完全廢掉，最後用 Claude Code `--chrome` 慢慢操作
- 判斷法則：一般查資料 → Web Search 為主；讀已登入的東西 → Claude in Chrome；抓沒 API 的服務 → Chrome 或 Playwright；寫 E2E → Playwright 沒得選
- 底層都在做同一件事（讓 AI 跟瀏覽器的控制介面講話），差別只在中間那層包裝 — 所以不要問「哪個最強」，要問「**我這件事卡在哪一關**」；與概念 20「選最淺可行的一層」是同一種思路

## 互動示範構想

一台「同一個網頁 × 三種讀法」的對照機。左邊三張讀法卡：`Web Search`／`Claude in Chrome`／`Playwright`；右邊是目標網頁，用抽象區塊呈現，每塊標好它的性質（伺服器端就組好／要跑起來才長出來／要登入才看得到／要點按鈕才出現／今天剛發布）。上方可切換目標頁面：公開說明文件、一般現代網站、你的蝦皮訂單頁、你要測的結帳流程。

選一種讀法，一道掃描光帶從網頁上方掃下來，每塊即時判定：讀得到就把內容線條填滿並打勾，讀不到就塌成空心虛線的空殼，右邊寫出理由。三種讀法的視覺外殼也不一樣 —— Web Search 是虛線框的「收錄副本」，標著「抄於 3 天前」；Claude in Chrome 是真的瀏覽器外殼，右上掛著綠點「你的登入狀態 · 已帶入」；Playwright 也是瀏覽器外殼，但明白標示「全新的隔離環境 · 沒有你的登入狀態」，旁邊蓋一個「可重複 · 能上 CI」的印章。

導演節奏：先用公開說明文件證明 Web Search 全綠、又快又便宜（而且沒開任何瀏覽器）→ 掀開「你讀的是收錄好的副本」這張底牌，副本戳章蓋下去 → **高潮**：換成一般現代網站，四塊區塊接連塌成空殼、標紅抖動，四個盲區一次現形 → 切到 Claude in Chrome，瀏覽器真的開起來，登入牆後面的區塊解鎖亮起 → 切到 Playwright，動態內容一樣讀得到，但登入牆那塊重新上鎖變紅，「乾淨隔離」的代價當場看見 → 蝦皮那一題：沒 API ＋ 要登入，只剩一條路，而且演出 CAPTCHA 那一拍 —— 畫面停住、控制權交還給你，你按下「我處理好了」它才繼續 → 最後 sandbox：自由切頁面 × 讀法，底下的判讀條即時算出「這一題卡在哪一關、走得通的是哪一條」。

## 課堂提問

- 你上一次叫 AI 幫你查資料，如果它拿到的只是一份三天前抄好的副本，答案會不會不一樣？你怎麼發現？
- 你手上有哪件事，是非得「用你已經登入的身分」才做得到的？那件事適合交給 AI 嗎？
- 「不要問哪個最強，要問我卡在哪一關」— 換到概念 20 的四層鑰匙上，這句話會變成什麼？
