## 一句話

聊天聊出來的成功，只成功一次；把它整理成 skill，才變成你每次都能重跑的工具。

## 三分鐘講稿

今天要教你們一個把 AI 從「玩具」變「生產力」的關鍵動作 — 做一個 skill。

先講情境。假設我今天要核對自費表，我在聊天裡跟 AI 一步一步喬：讀這個檔、跟那個檔比對、有問題標出來、最後輸出一份報表。喬了幾輪，終於一次跑對了。很多人到這裡就結束了，開心關掉。但問題是 —— 下禮拜你要再做一次，又要從頭喬一遍。這太浪費了。

所以成功之後，第一件事不是關掉，是**固化它**。你直接跟 AI 說：**「把整個驗證流程整理成一個完整的 skill，包含所有輸入項目、輸出規格。」** 它就會把你剛剛喬出來的那套流程，蒸餾成一份標準化的 skill 文件。

接下來走這幾步：

第一，**下載 skill 包**。它會給你一個 zip 或一個資料夾，裡面就是那份 SKILL.md 加相關檔案。

第二，**裝進 Claude**。到設定裡（Customize → Skills），或是放進你的專案資料夾，把這包東西掛上去。

第三，**用斜線 trigger**。裝好之後，你在對話框打一個 `/`，斜線選單就會亮出你剛做的那個 skill，選它 — 整套驗證流程就自動跑起來，不用你再一步一步喬。

第四，**測試一遍**，確認它跟你當初喬成功的那次結果一樣。對了，就收工。

這裡要先破一個迷思：**md 檔不等於 skill。** 很多人以為我寫一個 .md 檔、裡面把流程講清楚，它就變 skill 了 —— 不是。md 只是一種文字格式，對 agent 來說沒有任何特殊意義，它跟你隨手貼的一段筆記沒兩樣。真正的 skill 有它自己的規範：要有一個以 skill 名稱命名的資料夾、裡面放一份大寫的 `SKILL.md`、再加上它需要的附檔。你得**參考那個格式、把它打包起來**，agent 才認得、斜線才 trigger 得到。所以「寫成 md」跟「做成 skill」是兩件事 —— 前者只是格式，後者才有 agent 意義。

那什麼東西該做成 skill、什麼不用？給你一個判斷準則：**流程固定、可複製性高、這進這出（同樣的輸入就要同樣的輸出）—— 這種就做成 skill。** 自費表核對就是標準例子，規格明確、每次都要重跑。反過來，**開放式的、不需要標準答案的、你要的是激盪跟討論 —— 那就聊天就好，不要硬做成 skill。** 因為 skill 會把流程鎖死，你等於是叫模型照著固定劇本做文字接龍；用在需要發散的場合，反而把它的彈性綁死了。

這裡有個要提醒的踩雷：**skill 放錯位置，斜線就 trigger 不到。** 不同家的 agent，skill 放的地方不一樣 — 有的在設定裡、有的要放專案資料夾。如果你打斜線找不到你的 skill，十之八九是位置放錯了。遇到就直接問，不要自己在那邊花半小時猜。

最後講一句真心話：**我給你們的那個整理 prompt 看起來小小一句，但你們自己寫的時候會蠻吃力的 —— 那是因為我練很久了。** 別氣餒，這是熟練度的問題，不是你不夠聰明。

## 關鍵重點

- Skill = 把一次聊天喬成功的流程，固化成每次都能重跑的工具
- 關鍵指令：「把整個驗證流程整理成完整的 skill，包含所有輸入項目、輸出規格」
- 標準四步：下載 skill 包 → 裝進 Claude（Customize→Skills / 專案資料夾）→ 斜線 `/` trigger → 測試
- md 檔 ≠ skill：md 只是格式、對 agent 沒意義；skill 要有「名稱資料夾＋大寫 SKILL.md＋附檔」並參考格式打包，才真的變 skill
- 何時做 skill：流程固定、可複製、這進這出 → 做 skill；開放式、不需要標準答案 → 聊天就好，skill 會把文字接龍鎖死
- 踩雷：skill 放錯位置就 trigger 不到，不同家 agent 放法不同 — 遇到直接問，別自己猜
- 好的 prompt 看起來小，寫起來難 — 那是練出來的熟練度

## 互動示範構想

一條三步驟流水線動畫：① 一張「聊天流程卡片」（讀檔 → 比對 → 輸出報表），標示「這次跑對了」；② 使用者按下「Hardening／固化」按鈕，卡片上的對話被蒸餾、壓縮成一份 `SKILL.md` 包（動畫：一堆對話泡泡收斂成一個檔案圖示）；③ 把 skill 包拖進 agent，對話框的斜線選單亮起、出現這個 skill，點一下 trigger，同一套流程一鍵重跑成功。可加一個「放錯位置」的錯誤示範：拖到錯的資料夾 → 斜線選單找不到 → 提示「位置放對才 trigger 得到」。

## 課堂提問
