## 一句話

每一次送出訊息，對 AI 來說都是全新的世界 — 你以為的「對話」，是每次都把整段歷史重新塞給它。

## 三分鐘講稿

跟 AI 說「幫我記住這個」的時候，背後發生了什麼事？答案讓我滿意外的 — LLM 根本沒有記憶。

每一次送出訊息，對 AI 來說都是全新的世界。它不記得你上一句說了什麼。你以為的「對話」，其實是系統把之前的對話紀錄重新塞進去，讓 AI「看起來」好像記得。第一輪送 `[system][msg1]`，第二輪送 `[system][msg1][回覆1][msg2]`— 每一輪都是整串重傳。

所以「幫我記住」的真相是：memory system 幫你把資訊寫進 external storage（外部儲存），下次對話開始前，再根據你的問題去「撈」相關的記憶，塞回 AI 的 input 裡。寫入、檢索、注入 — 這整套機制，就是現在 AI Agent 架構的核心。

理解 stateless 之後，很多日常現象都解釋得通了：為什麼聊到後面 AI 回答越來越不對？因為對話歷史越來越長，擠壓了 context window 裡其他內容的空間。為什麼開新對話它就「忘光光」？因為根本沒有東西被真的記住 — 除非有 memory system 幫忙。

怎麼「洗白」回來？開新 session，手動把關鍵 context 重新餵進去 — 等於自己當了一次 memory manager。

這是整堂課最重要的一個地基：AI 的全部世界，就是這一次 API call 塞進去的那段文字。

## 關鍵重點

- LLM 沒有記憶 — 每次 API call 都是從零開始的全新世界
- 「對話感」是假象：harness 每輪都把完整歷史重新組裝送過去
- 「幫我記住」= 寫進外部儲存；「你記得嗎」= 觸發檢索再塞回 input
- 聊越久越不準，是因為歷史擠壓了 context window 的空間
- Memory 系統的本質：「在有限的桌子上，決定每次放什麼上去」

## 互動示範構想

畫面是一個聊天視窗 + 旁邊一個透明的「API call 內視鏡」。使用者輸入「我叫小明」、再問「我叫什麼？」— 內視鏡顯示每次送出時，整串歷史（system prompt + 所有舊訊息）被重新打包送出的動畫，AI 答對。然後按下「關掉歷史重送」開關，再問一次「我叫什麼？」— 內視鏡裡只剩孤零零的一句話，AI 一臉茫然答不出來。一個開關，讓「stateless」被親眼看見。
