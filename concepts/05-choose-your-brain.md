## 一句話

不是每件事都要用最強的模型 — 殺雞焉用牛刀，但雞太硬的時候，也別再拿水果刀硬砍。

## 三分鐘講稿

每次要用 AI，你其實都在做一個選擇：這顆大腦，要多聰明？

這件事很多人沒意識到，但它每天都在影響你。市面上一堆模型，強的、弱的、貴的、便宜的，差別在兩個地方：一個是它多聰明，一個是它的記性有多大 — 也就是 context window。

先講記性。你可以把 context window 想成一顆大腦一次能記住多少字。**100 萬 token 大概是 50 萬個中文字**（英文的話再除以一，因為一個英文單字常常拆成好幾個 token）— 那基本上是一整本小說的記憶量。**20 萬 token，就是拿來做小任務用的**，處理個文件、回個信、對個表，綽綽有餘。

那如果記性不夠會怎樣？我跟你講一個很實際的現象：一顆 128k 的模型，你連續問它六、七十個問題之後，它就開始「凸槌」了 — 前面講過的忘記、開始一本正經地亂編。**幻覺跟遺忘，就是這樣來的。** 不是它壞掉，是它的桌子塞滿了，舊的東西被擠出去了。

再講聰明。難題、要規劃、要動腦想的 — 你就選 context window 大、模型強的那一檔。純聊天、隨口問問、寫個罐頭回覆 — 選最便宜的就好。這就是「殺雞焉用牛刀」，別拿最貴的模型去做最無聊的事。

但這句話反過來也成立，而且更重要：如果你發現 sonnet 一直亂講、怎麼講都講不通，**別在那邊跟它耗，馬上換 opus。** 這時候不是你 prompt 寫不好，是這顆大腦就是不夠力。換一顆更強的，一句話就通了。

所以記住這個心法：先看任務有多難、要記多少東西，再決定用哪顆大腦。這個選擇做對了，你會省下一堆來回鬼打牆的時間。

## 關鍵重點

- 選模型 = 選大腦，看兩件事：多聰明（模型強度）＋ 記性多大（context window）
- 100 萬 token ≈ 50 萬中文字 ≈ 一本小說的記憶；20 萬 token 適合小任務
- 128k 的模型連問六、七十題就開始幻覺、遺忘 — 這是記性塞滿的自然結果
- 難題／規劃／思考 → 選強模型；純聊天 → 選最便宜的（殺雞焉用牛刀）
- 反過來也成立：sonnet 一直亂講，別硬凹，馬上換 opus

## 互動示範構想

一根「任務難度滑桿」，左端是「隨口聊天」、右端是「策略顧問」。使用者拖動滑桿，右邊即時推薦對應的模型檔位（便宜快 ↔ 強而貴）。旁邊並排三根「記憶量體比較條」（1M / 200k / 128k），使用者可以一題一題把問題塞進去，看到某一檔在第六、七十題時開始「掉字、亂答」變灰 — 親眼看到幻覺與遺忘是怎麼發生的。

## 課堂提問

- 你今天用 AI 做的事情，有哪些其實用最便宜的模型就夠了？
- 「怎麼講都講不通」的時候，你會先懷疑自己的 prompt，還是先換模型？為什麼？
- 如果一顆模型記得住 50 萬字，為什麼還會「忘記」你三分鐘前說的話？
