# 互動教學網站拆解分析 — 我們的 demo 差在哪、怎麼補

> 2026-07-22 實地拆解（Playwright 進站驗證 tech stack）+ 已知經典案例。目的：討論優化方向，還沒動工。

---

## 一、實地拆解

### 1. The Evolution of Trust（Nicky Case）— 互動教學的天花板
- **Tech（實測）**：PIXI.js（單一 canvas 舞台）+ Howler.js（**音效**）+ TweenJS（緩動）+ 自製 `Slideshow.js`
- **關鍵架構**：整個作品就是一個 **Slideshow** — 拆成幾十個「beat」（節拍），一個 beat 只講一件事，玩家按「下一步」推進。原始碼裡就有 `Slideshow.js / TextBox.js / Slider.js / Scratcher.js` 這種「導演零件」
- **視線引導**：**單一 canvas 舞台 = 永遠只有一個焦點**。新元素進場必有動畫+音效，眼睛自然跟著走
- **Motion**：所有東西都是 tween 進場（彈跳、滑入），角色有表情，按下按鈕有「juice」（縮放+音效）
- **節奏**：先手把手教（guided）→ 最後才開放 sandbox 自由玩

### 2. Seeing Theory（Brown 大學）— 學術美感標竿
- **Tech（實測）**：D3.js + SVG（4 個 svg/頁）
- **關鍵架構**：**一屏一概念**。左文右圖分欄，右邊永遠只有「一個」互動圖，按鈕就 1-2 顆（Flip the Coin / Flip 100 times）
- **視線引導**：畫面 70% 是留白。互動觸發後**只有數據視覺在動**，其他全靜止
- **Motion**：D3 transition — 硬幣拋起、長條圖長高，每次點擊都有一段「値得看」的動畫回饋

### 3. R2D3（A Visual Introduction to ML）— Scrollytelling 標竿
- **架構**：滾動 = 敘事推進。文字小卡逐段浮現，主視覺（決策樹）跟著滾動位置變形／飛散／重組
- **視線引導**：**主視覺永遠固定在畫面中，變化的只有它** — 你滾動，它演化，視線從不用搬家

### 4. Neal.fun — 玩具感
- 進場零說明成本：第一眼就知道要按哪裡（一顆大按鈕/一個大物件）
- 每次互動都有誇張回饋：數字暴衝、物件爆開、音效
- 資訊是「玩出來的」，不是「讀出來的」

### 5. Awwwards 系（Lando/Igloo 這類）動效 stack 常規
- **GSAP + ScrollTrigger**（業界標配）、Lenis 平滑滾動、SplitType 文字逐字動畫、spring 物理緩動
- 特徵：誇張的進出場（字會飛、模糊變清晰、scale 1.2→1）、慢速大動作（0.8-1.2s）配 `cubic-bezier(.16,1,.3,1)` 這類過衝曲線

## 二、提煉出的六條法則

1. **Beat 節奏**：一次只教一件事。所有頂級教學互動都是「slideshow of beats」，不是 dashboard
2. **單一焦點**：畫面上同時會動的東西 ≤ 1。新焦點進場 = 舊焦點退場（dim/縮小/離場）
3. **Juice**：每次點擊必有 100ms 內的誇張回饋（縮放彈跳+顏色+可選音效）— 這是「炫」的真正來源，不是特效多
4. **先導遊後放生**：guided tour（按下一步走完核心敘事）→ sandbox（自由亂玩）
5. **旁白是主角**：解說文字大（22px+）、位置固定（同一處出現）、一次一句
6. **動畫值得看**：狀態轉換不瞬移 — 貨物要飛走、token 要點亮、數字要滾動

## 三、對照診斷 — 我們的 demo 為什麼「亂」

| 問題 | 現狀 | 違反 |
|---|---|---|
| ❌ Dashboard 症 | 一進 demo 所有面板/按鈕/圖例同時攤開（例：compaction 一屏塞貨車+倉庫+按鈕列+計分） | 法則 1、2 |
| ❌ 沒有視線動線 | 左邊在動、右邊也在動、下面還有說明在閃 | 法則 2 |
| ❌ 旁白弱 | 引導語固定一段小字（15-17px）待在頂部，重要事件的旁白混在角落 | 法則 5 |
| ❌ 回饋平淡 | 按鈕按下去只有狀態變化，沒有 pop/彈跳/音效 | 法則 3 |
| ❌ 無節奏 | 除了 tool-use 有步進，其他 demo 都是「全部功能同時可按」 | 法則 1、4 |
| ❌ 轉場瞬移 | 很多狀態切換是 innerHTML 重繪，不是動畫過渡 | 法則 6 |
| ⚠️ 字級 | 已加大過一輪，但「事件旁白」還是不夠大 | 法則 5 |

外層（你說很棒的部分）其實已經符合法則：一屏一概念、大字、單焦點 — **問題全集中在 demo 內部**。

## 四、優化方向（供討論）

### 方案 A：「導演框架」DemoStage ⭐ 我最推薦
做一個共用的 beat 框架（≈ 自己的迷你 Slideshow.js），所有 demo 改掛在上面：
- 每個 demo 拆成 3-6 個 beat；底部大旁白條（24px，一次一句，打字機或滑入）+「下一步 →」
- **Spotlight 系統**：目前 beat 的主角亮、其他元素自動 dim 到 25% + 模糊
- 最後一個 beat = sandbox 模式，全部解鎖自由玩
- 工作量：框架 1 次 + 27 個 demo 改造（可分批，先做入門 16 個）
- 效果：直接解決「亂」，質感翻倍，是結構性根治

### 方案 B：Motion/Juice 升級（可與 A 疊加）
- 引入 **GSAP**（或自寫 300 行 spring/tween 工具）統一動效語言：進場滑入+過衝、按鈕 pop、數字 count-up、錯誤 shake、成功 confetti 粒子
- demo 內狀態轉換全部改成 tween（貨物飛走、卡片折疊）
- 工作量：中。一套 motion token + 各 demo 套用

### 方案 C：音效（Howler，預設關、一鍵開）
- 5-6 個音：點擊 tick、成功 chime、錯誤 thud、compaction whoosh、打字聲
- 上課投影時超加分；工作量：小（音效檔可用 Web Audio 合成，零素材）

### 方案 D：Ch1 旗艦 scrollytelling（R2D3 式）
- 把「文字接龍」做成滾動敘事：滾動時 token 一顆顆落下接龍、機率條跟著長 — 作為網站開場的 wow
- 工作量：中大，單點爆發

### 建議組合
- **第一輪：A + B**（結構根治 + 動效升級）— 「亂」和「不炫」一次解決
- **第二輪：C**（音效點睛，上課現場效果好）
- **第三輪：D**（開場旗艦，對外展示用）

你看方向 OK 嗎？或是你想先只挑 2-3 個代表性 demo（例如 Skill、Compaction、文字接龍）做成 A+B 的樣板，驗收質感後再全面鋪開？
